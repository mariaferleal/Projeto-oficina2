# Processo de desenvolvimento

O desenvolvimento segue o Scrum, com dois sprints e uma revisão ao final de cada um.

## Issues no GitHub

Cada funcionalidade vira uma issue, com critérios de aceite e testes esperados. Commits e pull requests citam a issue, para que cada entrega possa ser ligada à necessidade que a originou.

## Quadro no Jira

O quadro Kanban tem as colunas Backlog, A fazer, Em andamento, Em revisão e Concluído. Cada card cita a issue do GitHub.

## Responsabilidades

O README registra as atividades e as responsabilidades de cada integrante. A autoria individual aparece nas issues, nos commits, nas revisões e nas entregas.

## Entrega de cada sprint

Ao final de cada sprint, a equipe envia um vídeo de até cinco minutos mostrando a aplicação funcionando, as funções feitas e os testes automáticos rodando. Os ajustes pedidos pelo professor viram issues e entram no quadro com prioridade.

## Artefatos mantidos no GitHub

- README com objetivo, escopo, instruções para rodar e responsabilidades
- Arquivos de configuração do ambiente, dependências e variáveis de exemplo
- Requisitos funcionais e não funcionais
- Diagrama de arquitetura e, se usados, links dos protótipos no Figma
- Estratégia de testes, scripts de testes e relatórios de cobertura
- Issues de cada sprint e link do quadro do Jira no README
